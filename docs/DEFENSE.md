# Демонстрация за 5–7 минут

## Вступление

«Исходная программа считала квадратный корень в double. Мы уточнили контракт, добавили комплексную длинную арифметику, отдельный символьный режим и пользовательский интерфейс. Продукт распространяется одним автономным HTML-файлом. Для пользователя нет установки, серверных зависимостей и аккаунтов».

## Порядок показа

1. **Отрицательные числа:** `sqrt(-1)` → `i`, `(2+3i)^2` → `-5+12i`. Назвать главную ветвь корня.
2. **Длинная арифметика:** `0.1+0.2` → `0.3`; `sqrt(2)` → увеличить вывод до 50. Сравнить с исходным `double`, у которого ограничены точность хранения и стандартный формат вывода.
3. **Аналитический режим:** `sqrt(8)` → `2*sqrt(2)`, `x+x` → `2*x`, `1/3` остаётся дробью.
4. **Ошибки:** `1/0`, `abc`, лишняя скобка, затем снова `sqrt(4)` → `2`. Показать, что ошибка не ломает приложение.
5. **GUI:** переключить русский/английский/испанский/китайский; изменить формат/точность вывода. Показать справку.
6. **Переносимость:** открыть скачанный HTML с выключенной сетью. Нет зависимости от GitHub для вычислений.
7. **Качество:** Actions, чёрный/белый ящик, E2E, измеренное покрытие с указанием границ.
8. **Жизненный цикл:** диаграмма Ганта, роли, бюджет, обновления/откат, очистка сеанса и удаление файла.

## Пояснения к проектным решениям

**Рост сложности до написания кода.** Требования к входу, точности, ошибкам, среде и сроку службы уже присутствовали в задаче или были добавлены позже. Ограничение объёма версии делает работу управляемой.

**Разделение численной и символьной арифметики.** decimal.js выполняет численную арифметику высокой точности обеих комплексных компонент. Nerdamer преобразует выражения символически. Библиотеки решают разные задачи.

**Граница заявленной точности.** 200 цифр — рабочая точность и формат результата, не доказанная погрешность. Потеря значимости возможна; используются защитные разряды и дополнительный проход, но для строгих гарантий нужна интервальная арифметика или оценка ошибки.

**Чёрный и белый ящик.** При проверке чёрным ящиком тест проектируется по контракту входа и выхода. При проверке белым ящиком учитываются ветви и состояния реализации. Это не совпадает с делением тестов на модульные и сквозные.

**Покрытие тестами.** Покрытие строк не доказывает корректность. Измеренные строки и ветви относятся к собственному ядру и сервисам; UI и сторонние библиотеки не входят в этот процент.

**Граница удаления.** Приложение не устанавливает службы и не создаёт собственного постоянного хранилища. Из браузера нельзя гарантированно стереть swap ОС, резервные копии, кэш и копии пользователя.

**Снижение затрат на поддержку.** Небольшой законченный продукт без сервера, базы и установщика требует меньше обслуживаемых частей. Автономный артефакт позволяет пользователю работать при недоступности GitHub. Открытый код сам по себе не гарантирует бесплатную поддержку.

**Выбор языка.** В расширенном задании C++ не был закреплён. Приложение написано на TypeScript с React; браузерный стек уменьшает число платформенных пакетов. При обязательном C++ понадобится отдельное решение, например портирование ядра в WebAssembly.

**Роль A/B-теста.** Правильность формул проверяют эталонные и математические тесты. A/B-тест годится для сравнения двух вариантов интерфейса по метрикам удобства при наличии пользователей и плана исследования.

**Долгий срок службы.** Исходный файл может оставаться неизменным, но окружение меняется. Нужны архив дистрибутива, проверка совместимости, владелец и бюджет; запрет исправления уязвимостей конфликтует с надёжностью.
