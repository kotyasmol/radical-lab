# Демонстрация за 5–7 минут

## Что сказать в начале

«Исходная программа считала квадратный корень в double. Мы уточнили контракт, добавили комплексную длинную арифметику, отдельный символьный режим и пользовательский интерфейс. Продукт распространяется одним автономным HTML-файлом. Для пользователя нет установки, серверных зависимостей и аккаунтов».

## Порядок показа

1. **Отрицательные числа:** `sqrt(-1)` → `i`, `(2+3i)^2` → `-5+12i`. Назвать главную ветвь корня.
2. **Длинная арифметика:** `0.1+0.2` → `0.3`; `sqrt(2)` → увеличить вывод до 50. Сравнить с исходным `double`, у которого ограничены точность хранения и стандартный формат вывода.
3. **Аналитический режим:** `sqrt(8)` → `2*sqrt(2)`, `x+x` → `2*x`, `1/3` остаётся дробью.
4. **Ошибки:** `1/0`, `abc`, лишняя скобка, затем снова `sqrt(4)` → `2`. Показать, что ошибка не ломает приложение.
5. **GUI:** переключить русский/английский/испанский/китайский; изменить формат/точность вывода. Показать справку.
6. **Переносимость:** открыть скачанный HTML с выключенной сетью. Нет зависимости от GitHub для вычислений.
7. **Качество:** Actions, чёрный/белый ящик, E2E, измеренное покрытие с указанием границ.
8. **Жизненный цикл:** диаграмма Ганта, роли, бюджет, обновления/откат, очистка сеанса и удаление файла.

## Вероятные вопросы

**Почему сложность выросла ещё до кода?** Мы выявили требования к входу, точности, ошибкам, среде и сроку службы. Часть сложности уже была в задаче, а часть добавили новые требования. Ограничение scope делает её управляемой.

**Зачем две библиотеки?** decimal.js выполняет численную арифметику высокой точности обеих комплексных компонент. Nerdamer преобразует выражения символически. Одно не подменяет другое.

**200 цифр означают 200 верных цифр?** Нет. Это рабочая точность и формат результата, не доказанная погрешность. Потеря значимости возможна; есть защитные разряды и дополнительный проход, но для строгих гарантий нужна интервальная арифметика/оценка ошибки.

**Что считать чёрным и белым ящиком?** Чёрный — тест проектируется по контракту вход/выход. Белый — по ветвям и состояниям реализации. E2E проверяет цепочку через GUI и может использовать black-box подход; unit-тест может быть black-box.

**Почему не заявить 100% покрытие?** Покрытие строк не доказывает корректность. Указываем реально измеренные строки/ветви и то, что UI/сторонние библиотеки не входят в данный процент.

**Как гарантировать бесследное удаление?** Можно гарантировать отсутствие собственных установленных служб/хранилищ и описать удаление файла. Нельзя из браузера гарантированно стереть ОС swap, бэкапы, кэш и копии пользователя. Требование нуждается в согласованной границе ответственности.

**Что за необычный способ снизить поддержку?** Предположение: закончить и зафиксировать небольшой продукт, убрать инфраструктуру и сервисные зависимости, распространять автономный артефакт. Ещё варианты — переиспользовать готовые устойчивые библиотеки и открыть исходники. Открытый код сам по себе не гарантирует бесплатную поддержку. Точную задумку преподавателя нельзя выдавать за известную.

**Почему не C++?** В расширенном списке язык не был зафиксирован. Браузерный стек уменьшает число платформенных пакетов. Если C++ обязателен, это отдельный constraint, и целесообразен C++→WebAssembly при сохранении интерфейса.

**Нужен ли A/B-тест?** Для проверки формул — нет: правильность проверяют эталонные и свойственные математике тесты. A/B может сравнить два интерфейса по метрикам удобства, если есть пользователи и вопрос исследования.

**Что значит «10 лет без изменений»?** Исходный файл может оставаться неизменным, но его окружение меняется. Нужны архив дистрибутива, проверка совместимости, владелец и бюджет; запрет исправления уязвимостей конфликтует с надёжностью.
