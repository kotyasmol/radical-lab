# Требования и границы версии 1.0

## Цель и допущения

Развить учебный пример вычисления квадратного корня в переносимое приложение с проверяемым поведением. Язык C++ не указан как обязательное ограничение в расширенном задании; выбран TypeScript/React с локальными вычислениями в браузере. Если преподаватель требует сохранить C++, это изменение входных требований: потребуется портирование ядра в WebAssembly или отдельная реализация.

«Длинные комплексные числа» трактуются как комплексные числа с десятичной многозначной арифметикой обеих компонент. «Аналитические выражения» — ввод формул и символьное упрощение, без уравнений/интегралов. «Заданная точность» — рабочие значащие цифры и независимое округление вывода, **не гарантированная абсолютная погрешность**.

## Функциональный контракт

Ввод: Unicode-строка; `−`, `×`, `÷`, `π` нормализуются. Десятичная точка или запятая; разделителей тысяч нет. `1,234` означает 1.234. Функции одноаргументные, поэтому запятая не используется для списка аргументов. Только документированные имена и операции; присваивания, массивы, доступ к свойствам, строки и скрипты запрещены. Имя переменной допустимо только в символьном режиме.

Численный режим возвращает одно главное значение в форме `a ± bi`. Вещественная/мнимая нулевая компонента не выводится; коэффициент ±1 перед `i` сокращается. `sqrt(-0)=0`, `0^0` и `ln(0)` — ошибки. `log` означает натуральный логарифм. Углы только в радианах. `2^3^2=512`; унарный минус слабее степени: `-2^2=-4`. Допустимо неявное умножение `2i` и `2(1+i)`, но не два числа через пробел.

Символьный режим упрощает исходное выражение средствами Nerdamer. В частности, `(x²−1)/(x−1)` может стать `x+1`, но условие `x≠1` сохраняется. UI всегда показывает это предупреждение. `re`, `im`, `conj` в этом режиме отклоняются. Результат — строка математического выражения, а не обещание решения любой задачи анализа.

## Ограничения и нефункциональные требования

- Рабочая и выводимая точность: целые 2–200, вывод не больше вычислений. По умолчанию 50/20.
- Внутренняя первая точность — P+30; дополнительная проверка — P+50. Округление half-even.
- Катастрофическая потеря значимости возможна; совпадение двух проходов не доказывает точность. Например, при слишком малой P оба прохода могут потерять единицу в `(1e1000+1)-1e1000`. Для точных алгебраических ответов используйте символьный режим. Не предназначено для критически важных расчётов.
- Длина: 4096 символов численно, 512 символьно; 512 токенов, глубина рекурсии парсера 64; длина числового литерала ≤1000 символов.
- Порядки ненулевых численных компонент — от −10000 до +10000. Выход за диапазон отклоняется, а не молча превращается в ноль.
- Целая степень по модулю ≤10000; символьные большие степени дополнительно ограничены; общий Worker-тайм-аут обязателен.
- Аргументы sin/cos/tan: модуль вещественной части ≤10⁶, мнимой ≤20000. Для exp: вещественная часть ≤20000 по модулю, мнимая ≤10⁶. Это бюджет вычислений, а не математическая область определения.
- Не более 4 секунд на задачу; после тайм-аута Worker уничтожается. Зависание/крах всего браузера или ОС этим не предотвращаются.
- История: последние 50 успешных результатов только в RAM, с точностью и временем; экспорт JSON по желанию.
- Сетевые запросы во время расчётов отсутствуют. Проверка обновления по кнопке ограничена шестью секундами; внешний GitHub-сайт видит обычные сетевые метаданные запроса.
- Целевой интерфейс: от 390 CSS px, клавиатура, видимый focus, семантические label/role и базовая автоматическая проверка WCAG A/AA. Это не сертификат полной доступности.
- Релизный критерий: зелёная CI, пройденные smoke-сценарии и проверенный автономный файл, нет известных блокирующих дефектов.

Поддержка «где угодно» ограничена платформенной матрицей. Браузеры без Workers/Blob/ES2022/HTML dialog, старые ОС, embedded webviews, корпоративный запрет JavaScript и файловые просмотрщики не входят в обязательную поддержку.
