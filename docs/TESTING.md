# Стратегия и отчёт тестирования

## Уровни и методы

«Чёрный/белый ящик» описывают знание внутренней структуры при проектировании теста; «unit/integration/E2E» — уровень проверки. Это разные оси, не взаимоисключающие категории.

| Вид                     | Реальные проверки                                                                                    | Где                                  |
| ----------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------ |
| Чёрный ящик             | Вход→выход: корни, комплексные операции, дроби, приоритеты, символы, точность                        | `tests/unit/engine.test.ts`, E2E     |
| Граничные значения      | 2 и 200 цифр, 1/201 отклоняются; длина, глубина, показатели; ноль, отрицательные и малые числа       | `engine.test.ts`                     |
| Классы эквивалентности  | Корректные вещественные/комплексные; неправильный синтаксис; недопустимые операции                   | `engine.test.ts`                     |
| Белый ящик              | Ветви стабильного sqrt/деления, unary precedence, отмена, тайм-аут, поздний ответ, исключение Worker | `engine.test.ts`, `services.test.ts` |
| Метаморфные             | `z*conj(z)=a²+b²` на сетке целых, `sqrt(n²)=n`                                                       | `engine.test.ts`                     |
| Интеграционные          | Parser→Decimal/complex→formatter, Parser→Nerdamer, Worker→UI                                         | оба набора                           |
| E2E / системные         | Ввод→расчёт→история, смена точности, 4 языка, экспорт, справка, очистка                              | `tests/e2e/app.spec.ts`              |
| Fault injection         | Первый Worker не отвечает: отмена/тайм-аут и успешная следующая задача                               | E2E + unit                           |
| Offline / переносимость | Файл открывается через `file://` при заблокированной сети                                            | E2E, 3 движка                        |
| Конфиденциальность      | Нет исходящих запросов расчёта, нет cookies/localStorage/sessionStorage, reload очищает историю      | E2E                                  |
| Доступность             | axe WCAG 2 A/AA и 2.1 AA; формы/клавиатура; отсутствие горизонтального overflow на 390 px            | E2E + осмотр                         |
| Регрессионные           | Весь набор на push/PR/tag; пороги покрытия останавливают CI                                          | GitHub Actions                       |
| Зависимости             | `npm audit --omit=dev --audit-level=high`, закреплённые версии                                       | CI                                   |

## Локально выполненная проверка

Первичный выпуск проверен на macOS Apple Silicon, Node 26.5.0 (CI использует Node 22), npm 11.17.0.

- **229 unit/интеграционных/метаморфных тестов прошли.**
- **33 E2E-проверки прошли:** 11 сценариев × Chromium, Firefox, WebKit.
- Компиляция TypeScript и production build прошли.
- Axe в тестируемом состоянии не нашёл нарушений выбранных правил; это не полная сертификация доступности.
- Интерактивный smoke выполнен также во встроенном браузере: комплексный расчёт и видимый результат.
- Дополнительно успешно завершена CI-матрица Windows/macOS/Ubuntu: по 229 тестов ядра и по 33 браузерных проверки на каждой ОС, всего 99 E2E-запусков. [Первый полный прогон](https://github.com/kotyasmol/radical-lab/actions/runs/36226859303); актуальное состояние релиза смотрите в Actions.
- Скриншоты: [desktop](screenshots/desktop.png), [mobile](screenshots/mobile.png).

Тестовые браузеры: Chromium 153.0.8010.12, Firefox 155.0, WebKit 26.6 из Playwright 1.63.0. Эти версии описывают тестовую среду, а не обещание наличия именно этих сборок у каждого пользователя.

Особенность теста WebKit: `setOffline(true)` в автоматизации блокировал сам переход к `file://` внутренней ошибкой движка. Для него HTTP(S) блокируется через маршрутизацию; файл и Blob Worker остаются доступны. Chromium/Firefox проверены с сетевым offline-флагом и блокировкой HTTP(S). Ни один вариант не может загрузить внешнюю библиотеку во время теста.

## Покрытие

Измеряется **собственный расчётный код, парсер, форматирование, словари, runner и updater**. React-компоненты и входной Worker-адаптер проверяются E2E, но не входят в эти проценты. Сторонние библиотеки не инструментируются. Поэтому число ниже нельзя называть «покрытием всего приложения».

| Метрика    | Первичный локальный замер | Порог CI |
| ---------- | ------------------------: | -------: |
| Строки     |          98.85% (260/263) |      90% |
| Ветви      |          95.90% (234/244) |      80% |
| Функции    |              100% (40/40) |      90% |
| Statements |          97.14% (306/315) |      90% |

Повторяемая команда: `npm run test:coverage`; машинный результат `coverage/coverage-summary.json`, HTML `coverage/index.html`. Точные цифры после изменения кода нужно пересчитать, а не копировать из этого отчёта. Строки абсолютных локальных путей в coverage не публикуются как исходники.

## Команды

```sh
npm ci
npm run test:coverage
npm run build
npx playwright install --with-deps chromium firefox webkit
npm run test:e2e
```

Для проверки одного движка: `npm run test:e2e -- --project=firefox`. HTML-отчёт Playwright создаётся в `playwright-report`; при падении сохраняется trace. В CI отчёты доступны как артефакты. Зависимости тестов закреплены в lock-файле.

## Что тесты не доказывают

- Все математические тождества на всём комплексном поле, особенно ветви и области определения.
- Правильность всех заявленных цифр произвольного плохо обусловленного выражения.
- Работу любой версии Safari только по прохождению Playwright WebKit.
- Десять лет совместимости, отсутствие всех уязвимостей и полное физическое стирание данных.
- Профессиональную лингвистическую проверку переводов.
- Работу всех физических ОС по локальному запуску: для этого выделена CI-матрица Windows/macOS/Linux. Смотрите фактический статус Actions для конкретной ревизии.

## Ручная приёмка перед защитой

1. Скачать HTML из опубликованного релиза на другую машину и отключить сеть.
2. `sqrt(-1)`, `sqrt(2)` с 50 цифрами, `(2+3i)^2`, `1/0`, затем корректное выражение.
3. Символьно `sqrt(8)`, `x+x`, `1/3`; проговорить ограничения области определения.
4. Переключить 4 языка, проверить справку и клавиатуру.
5. Экспортировать историю и открыть JSON текстовым редактором.
6. Проверить обновление, очистить сеанс, закрыть и удалить переносимый файл.
7. Показать успешную CI, покрытие и диаграмму Ганта.
